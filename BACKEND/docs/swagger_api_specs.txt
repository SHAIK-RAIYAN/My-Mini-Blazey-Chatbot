PATCH
/employees-api/employees/{id}
Update employee (partial PATCH)



Partial update of a single employee by ObjectId (404 if not found). HR / admin only (authorization-gated). All CreateEmployeeDto fields are accepted but every one is OPTIONAL on PATCH; send only what changes. Enforces field immutability rules before writing (403 when a locked field is changed). When emergency contacts are sent, re-validates exactly one primary contact; recomputes the probation end date, mirrors the address when flagged same-as, and re-resolves the reporting-manager snapshot when the manager changes. A manager reassignment or explicit clear fires notification mail to the affected manager(s) and the employee; no-op resaves send no mail.
Required path parameters
id: (REQUIRED): (API call - GET /employees-api/employees/search -> data[*]._id). ObjectId format, the employee document id.

POST

Create a new employee



Creates one employee in the current tenant. HR / admin only (authorization-gated). Work email and userId must be unique (409 on collision); the legal entity must belong to this tenant (400 if not); a primary emergency contact must be present. Default/system agents cannot be created here (403). Derives userId from the work-email local part when omitted, computes the probation end date, mirrors the address when flagged same-as, resolves the reporting-manager snapshot, generates employeeId, and tokenizes government-ID numbers in the vault before insert (no raw gov-ID is ever persisted).

Create Task



Create Task Creates a new task or subtask with automatic ID generation and customer ID population from the associated project.
For Creating a Task:
Use POST /task
Task ID is generated automatically, and the customer ID is automatically populated from the associated project.
Required body fields
project: (REQUIRED): (User). Types.ObjectId, Project ID (MongoDB ObjectId) where task will be created
title: (REQUIRED): (User). string, Task title (1–500 characters)
type: (REQUIRED): (User). string, Task category — the task's LEVEL in the hierarchy (NOT task type). Enum: Task | Child Task | Sub Task. See "Task hierarchy" below for which parent each level requires. Do NOT confuse with taskType below — type is the category and is required; taskType is an optional classification.
priority: (REQUIRED): (API call - GET /project-api/project-settings?type=PRIORITY → data[ * ]._id). Types.ObjectId, Priority level ID
status: (REQUIRED): (API call - GET /project-api/project-settings?type=STATUS → data[ * ]._id). Types.ObjectId, Current status ID
Optional body fields
description: (OPTIONAL): (User). object, Task description with optional linked attachmentsmessage: (OPTIONAL): string, The description text
linkedAttachment: (OPTIONAL): string[], Array of attachment IDs
taskType: (OPTIONAL): (User). string, Task type classification (distinct from the required type category). Enum: Story | Feature | Bug | Enhancement | Epic. Omit when unsure — do not block the request on this field.
customer: (OPTIONAL): (User). Types.ObjectId, Customer ID (auto-populated from project if omitted)
documents: (OPTIONAL): (User). Types.ObjectId[], Array of document attachment IDs
sla: (OPTIONAL): (User). number, Service Level Agreement time in hours (min: 0)
estimatedEffort: (OPTIONAL): (User). number, Estimated effort in hours (min: 0)
actualEffort: (OPTIONAL): (User). number, Actual effort spent in hours
startDate: (OPTIONAL): Date, Task start date
dueDate: (OPTIONAL): Date, Task due date
endDate: (OPTIONAL): Date, Task completion date
completedDate: (OPTIONAL): Date, Task completed date
assignee: (OPTIONAL): (API call - GET /api/employees/search → data[ * ]._id). Types.ObjectId, Primary employee ID assigned to the task
assignees: (OPTIONAL): (API call - GET /api/employees/search → data[ * ]._id). Types.ObjectId[], Additional assignee employee IDs (multi-assignee support)
watchers: (OPTIONAL): (API call - GET /api/employees/search → data[ * ]._id). Types.ObjectId[], Watcher employee IDs — notified on all task changes
ccList: (OPTIONAL): (API call - GET /api/employees/search → data[ * ]._id). Types.ObjectId[], CC list employee IDs (max 50, unique)
labels: (OPTIONAL): (API call - GET /project-api/project-settings?type=LABEL → data[ * ]._id). Types.ObjectId[], Array of label IDs (max 50, unique)
mileStones: (OPTIONAL): (User). string[], Array of milestone names (max 20, unique)
milestone: (OPTIONAL): (User). Types.ObjectId, Milestone ObjectId this task belongs to
taskGroupId: (OPTIONAL): (User). Types.ObjectId, Task group / sprint section ID
task: (OPTIONAL): (User). Types.ObjectId, Parent task ID. REQUIRED when type is "Child Task" or "Sub Task"; ignored for top-level "Task". Stored as parentTask in the database.
parentTask: (OPTIONAL): (User). Types.ObjectId, Alias for "task" field
parentTaskKey: (OPTIONAL): (User). string, Parent task human key (e.g. "AMAZ-3"). Preferred when you only have the key shown in the UI and not the Mongo ObjectId — server resolves it to parentTask._id. Only used if task and parentTask are both absent.
Task hierarchy
Tasks form THREE levels, chosen with type and linked with task / parentTask:
typeLevelParent requiredCan containTaskTop level (main task)No — omit task/parentTaskChild Tasks and Sub TasksChild TaskSecond levelYes — a TaskSub TasksSub TaskThird level (leaf)Yes — a Task or a Child TaskNothing
Notes:
The level is stored, not inferred from depth. Creating a Child Task means sending type: "Child Task" — a Sub Task parented to a Task is NOT the same record as a Child Task.
Reads nest the tree into childTasks[] and subTasks[]: a Task carries both, a Child Task carries only subTasks[], a Sub Task carries neither.
Assignee cannot be set directly on a Child Task or Sub Task — it is inherited from the parent and cascades down.
Personal tasks (isPersonal: true) are flat: only type: "Task" is meaningful.
Dependent look-up APIs
GET /api/employees/search - supplies employee _id values for assignee, assignees, watchers, and ccList fields.
GET /project-api/project-settings?type=PRIORITY - supplies priority _id values.
GET /project-api/project-settings?type=STATUS - supplies status _id values.
GET /project-api/project-settings?type=LABEL - supplies label _id values.

For Updating Tasks:
