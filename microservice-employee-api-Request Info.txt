

### Global Configuration & Authentication

* **Base URL**: `http://api.stg.blazeup.ai/employees-api` and `APP_CONTEXT=employees-api` in `.env`)
* **Global Prefix**: `/${APP_CONTEXT}` (`/employees-api`)
* **Standard Headers**:
  ```http
  Authorization: Bearer <JWT_TOKEN>
  Content-Type: application/json
  ```

  ```json

    "message": "Error description string or array of validation errors",
    "error": "Bad Request"
  }
  ```

## 1. POST `/employees-api/employees` — Create a New Employee

* **Method**: `POST`
* **Full URL**: `http://api.stg.blazeup.ai/employees-api/employees`
* **Controller**: [EmployeeController.create](file:///e:/VS%20CODE/Blazeup/blazeup-microservice-employee/src/modules/employee/controllers/employee.controller.ts#L48-L57)
* **Access**: HR / Admin only (guarded by `@AuthMethod(IS_AUTHORIZATION_KEY)`)

### Request Headers
```http
Content-Type: application/json
Authorization: Bearer <JWT_TOKEN>
```

### Request Payload (`CreateEmployeeDto`)

#### Required Fields:
* `employmentType` *(String enum)*: `"REGULAR"` | `"CONTRACT"` | `"INTERN"` | `"CONSULTANT"`
* `employmentBasis` *(Object)*: Reference object `{ "_id": "<24-hex-ObjectId>", "name": "Full Time" }`
* `hireDate` *(String)*: Date in `"YYYY-MM-DD"` format
* `personalInfo` *(Object)*:
  * `firstName` *(String)*: Required, sanitized string
  * `lastName` *(String)*: Required, sanitized string
  * `dob` *(String)*: Date in `"YYYY-MM-DD"` format
  * `gender` *(String enum)*: `"MALE"` | `"FEMALE"` | `"NON_BINARY"` | `"PREFER_NOT_TO_SAY"`
  * `contact`:
    * `workEmail` *(String)*: Valid unique corporate email address
* `employmentDetail` *(Object)*:
  * `department` *(Object)*:
    * `_id` *(String)*: 24-character hexadecimal MongoDB ObjectId
    * `departmentId` *(String)*: 12-digit hierarchy subnet code (e.g. `"100103000000"`)
    * `name` *(String, optional)*: Department name
  * `jobTitle` *(Object)*:
    * `_id` *(String, optional)*: 24-character hexadecimal MongoDB ObjectId
    * `name` *(String, optional)*: Job title name

> [!IMPORTANT]
> **Validation rules to keep in mind:**
> 1. If `personalInfo.emergencyContacts` is supplied, **exactly one contact must have `"isPrimary": true`** (`assertPrimaryEmergencyContact`).
> 2. `personalInfo.maritalStatus` is optional in the DTO; if omitted, the service automatically defaults it to `"PREFER_NOT_TO_SAY"`.
> 3. `personalInfo.contact.userId` is optional; if omitted, it is auto-derived from the prefix before `@` in `workEmail`.
> 4. System default agents (`internalEmployee.isDefault: true`) cannot be created through this endpoint (`403 Forbidden`).

## 2. GET `/employees-api/employees` — List Employees

* **Method**: `GET`
* **Full URL**: `http://api.stg.blazeup.ai/employees-api/employees`
* **Controller**: [EmployeeController.list](file:///e:/VS%20CODE/Blazeup/blazeup-microservice-employee/src/modules/employee/controllers/employee.controller.ts#L61-L103)
* **Access**: RBAC-gated. Non-privileged regular employees are restricted to `scope=team` (or targeted lookup with `employeeId`).

### Request Headers
```http
Authorization: Bearer <JWT_TOKEN>
```

### Query Parameters (`FilterEmployeeDto`):
* `page` *(number, optional)*: Page index (default: `1`)
* `limit` *(number, optional)*: Page size (e.g. `20`)
* `sort` *(string, optional)*: Sorting field (e.g. `hireDate:desc`)
* `search` *(string, optional)*: Full-text match on `employeeId`, legal name, or `workEmail`
* `employeeId` *(string, optional)*: Exact human-readable ID match (case-insensitive)
* `status` *(string enum, optional)*: `"ACTIVE"` | `"INACTIVE"` | `"SUSPENDED"`
* `employmentType` *(string enum, optional)*: `"REGULAR"` | `"CONTRACT"` | `"INTERN"` | `"CONSULTANT"`
* `employmentBasis` *(string, optional)*: Name of employment basis (e.g. `"Full Time"`)
* `employmentRegion` *(string enum, optional)*: `"SOUTH_ASIA"` | `"SOUTHEAST_ASIA"` | `"MIDDLE_EAST"` | `"NORTH_AMERICA"` | `"EUROPE"` | `"OTHER"`
* `workMode` *(string enum, optional)*: `"ON_SITE"` | `"REMOTE"` | `"HYBRID"`
* `departmentId`, `divisionId`, `legalEntityId`, `reportingManagerId`, `jobTitleId`, `timePlanId` *(string ObjectId, optional)*
* `campusId` *(string ObjectId or comma-separated ObjectIds, optional)*
* `hireDateFrom`, `hireDateTo` *(string, optional)*: `"YYYY-MM-DD"`
* `lastWorkingDayFrom`, `lastWorkingDayTo` *(string, optional)*: `"YYYY-MM-DD"`
* `isActive` *(boolean, optional)*: `true` | `false`
* `includeInternal` *(boolean, optional)*: `true` to include Blazey bots/agents (default `false`)
* `includeDeleted` *(boolean, optional)*: `true` to include soft-deleted records (default `false`)
* `skill` *(string, optional)*: Free-text match on skill name
* `jobTitle` *(string, optional)*: Free-text match on job title
* `groupBy` *(string enum, optional)*: `department` | `reportingManager` | `campus` | `legalEntity` | `jobGrade` | `employeeType` | `division` | `workMode`
* `responseFields` *(string, optional)*: Comma-separated whitelist of fields to project (e.g. `?responseFields=employeeId,personalInfo,employmentDetail,status`)
* `scope` *(string enum, optional)*:
  * **View scopes**: `"company"` | `"joined"` | `"left"` | `"team"`
  * **Directory dispatch scopes**: `"internal"` | `"search"` | `"by-phone"` *(requires `&phone=<number>`)*

### Request Payload:

###  Notes Regarding Initial Documentation

2. **`GET /my-profile` routing**:
   * Controller is mounted as `@Controller('employees/my-profile')` with `@Get()`, making the URL `GET /employees-api/employees/my-profile`. It does not accept or require any parameters or request body; it strictly parses the JWT payload.
3. **`PATCH /avatar-visibility`**:
   * Controller is mounted inside `EmployeeProfileController` (`@Controller('employees/:id')`) as `@Patch('avatar-visibility')`.
   * The URL is `PATCH /employees-api/employees/:id/avatar-visibility`.
   * Requires `{ "show": true | false }`.
   * It specifically verifies `callerId === targetId` and throws `403 Forbidden` if attempting to change someone else's visibility.
4. **`POST /employees` emergency contacts constraint**:
   * When `emergencyContacts` array is sent, the code explicitly enforces that **exactly one contact has `"isPrimary": true`**. Sending zero or multiple primary contacts causes a `400 Bad Request`.
5. **Partial PATCH vs Section PATCH**:
   * `PATCH /employees-api/employees/:id` is a root record patch (`UpdateEmployeeDto`). When called by a regular employee (self), HR-managed fields (`employmentDetail`, `workMode`, `probation`, `status`, etc.) are stripped silently to allow personal edits without throwing an error.
   * `PATCH /employees-api/employees/:id/personal-info` is dedicated to the personal-info section and triggers name/photo change cascades across reporting manager snapshots in MongoDB and life-event queues.
